# v5.0.0 Release Notes

## Summary
A major release that introduces an asynchronous factory pattern for initializing timer managers and migrates internal directory searching to an asynchronous implementation for better performance and error handling.

## Added
- Added `static async create()` method to `JSONLTimersManager` and `PlainTextTimersManager`. This provides a safer way to initialize managers that require asynchronous file system checks.
- Improved documentation in `README.md` with updated examples using the new asynchronous initialization pattern.

## Changed
- **Internal Initialization**: The `TimersStore` is now initialized immediately during manager creation rather than being lazily loaded during the first operation.
- **Dependency Updates**: Updated `uuid` dependency to `^13.0.0`.
- **Search Logic**: Refactored the internal root directory search logic to be fully asynchronous and use `fs/promises`.

## Breaking Changes
- **Manager Instantiation**: The constructors for `JSONLTimersManager` and `PlainTextTimersManager` are now `protected`. Direct use of `new JSONLTimersManager()` or `new PlainTextTimersManager()` will now cause a TypeScript error. You **must** use the static `create()` method:
  ```typescript
  // Old way (No longer works)
  // const manager = new JSONLTimersManager();

  // New way
  const manager = await JSONLTimersManager.create();
  ```
- **Asynchronous `searchRoot`**: The `searchRoot` utility function is now `async`. If your project relies on this internal function, you will need to `await` its result.
